### Blocker

**E2EA-F01 — Re-importing a seeded workbook on the KVKK-masked stack writes real instructor names; the stack's
mask command cannot repair a running stack.** Severity: blocker (KVKK; testers commit screenshots).
- Repro:
  1. Gracious stack, as `admin@smartsched.local`, open /import › Ders planlama listesi.
  2. Select term "Bahar 2026" and choose `smartsched/backend/tests/fixtures/bahar_derslik_planlama_listesi_v5.xlsx`.
  3. Press Önizle. The preview reads "Öğretim elemanları 402 yeni".
  4. Press Uygula (job 14, ≈ 14:25 UTC).
  5. Run `python3 -I scripts/record/kvkk_mask.py <stack-g>/rec.db --verify`: it prints `left 430`. It lists name
     shapes only, as instructors with two or three full words.
  6. Run `REC_WORKDIR=<stack-g> scripts/record/stack.sh mask`: `sqlite3.IntegrityError: audit_events is
     append-only`, "kvkk mask failed". A second `--verify` still prints `left 430`. The API stays healthy.
- Observed: the workbooks hold full names; the stack masks them only once, after seeding
  (`scripts/record/kvkk_mask.py` docstring; `stack.sh:161`). Each UI re-import matches nothing, so it creates new
  instructors with full names: 402 for Bahar. Jobs 8–10 by other testers were previews only and wrote nothing.
  The same mismatch probably explains why an unchanged weekly grid previews "8.519 kayıt değişecek" (Bahar) and
  "1.080" (Güz) and rewrites every assignment (9,043 and 3,150): the masked block labels differ from the file.
  RF-B, RF-F (`rf-f.spec.ts`), the smoke import step and the council re-run all re-import these files.
- Expected: a re-import on a recording stack never brings names back; the repair tool works on a running stack.
- Proposed fix:
  1. Now: restore `rec.snapshot.db` (orchestrator).
  2. In `scripts/record/stack.sh` `cmd_up`, keep masked copies of the seven workbooks in `$REC_WORKDIR/fixtures`
     (run kvkk_mask's replacement over the workbook cells with `--names`). Point the queue items and specs at them
     through `E2E_FIXTURES_DIR`, which is already read in `e2e/helpers.ts:18`.
  3. Have `kvkk_mask.py` skip `audit_events`, or mask it in a migration-sanctioned way, so `stack.sh mask` can run
     on a live stack.
  4. Until then, mark every queue item that re-imports a seeded file "fresh stack only".

  `ImportDiff.safeParse` fails on them and the whole diff is dropped. The Bahar preview (job 13) rendered only

- Where:
  - backend `smartsched/backend/app/council/dryrun.py:114` returns the tuple `pk` for composite keys;
  - frontend `smartsched/frontend/src/lib/api/rf-admin.ts:30`: `id: z.union([z.number(), z.string()])`;
  - `rf-admin.ts:47-49`: one bad row fails the whole parse.
- Fix:
  - in `dryrun.py:114`, return `":".join(map(str, pk))` for composite keys;
  - in `rf-admin.ts:30`, accept `z.array(z.union([z.number(), z.string()]))`, or use `z.unknown()` and stringify;
  - in `rf-admin.ts:47-49`, parse `counts` separately from `rows` so a bad row still shows the totals;
  - add a vitest case with a composite id.
