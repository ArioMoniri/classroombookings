## 4. Findings

### AS20-F01 · blocker · The sign-in form sends the password in the URL when submitted before hydration
- **Status:** fixed in FIX-D as HB18-F02 (sign-in forms are FIX-D's lane): `auth/credential-form.ts` method=post + `/api/auth/no-script` 303, submit disabled until hydrated, proxy strips credential query params.
- **Repro:**
  1. Open http://127.0.0.1:19901/login with JavaScript off, or on a slow first load before React hydrates.
  2. Type a username and password and press "Giriş yap".
- **Observed:** the browser does a native GET to `/login?username=…&password=…`. It happened live during a persona sign-in (the query held the real persona password, which is not reproduced here). I reproduced it with dummy values and JS off: `form attrs={"method":null,"action":null}` → `/login?username&password`. The password ends up in browser history, proxy and nginx access logs, and the Referer of the next request. My scripts had to wait for network idle before typing to avoid it.
- **Expected:** credentials are never placed in a URL.
- **Where:** `smartsched/frontend/src/components/auth/local-sign-in.tsx:165`, a `<form onSubmit=… noValidate>` with no `method`.
- **Fix:**
  - Add `method="post"` (and an `action` that answers 303 to /login, or a server action) so a pre-hydration submit is a POST.
  - Disable the submit button until hydrated (`useEffect` sets ready).
  - Have nginx and the middleware strip and refuse `password` query parameters on /login.
