## 2. Setup and method

**Viewports and context:** 1440×900 mouse; 390×844, 768×1024 and 844×390 touch (isMobile, hasTouch, DPR 2); tr-TR, Europe/Istanbul. One browser at a time, `nice -n 10`.

**Sign-in:** every script waits for hydration (networkidle, then a hydrated, enabled submit) before typing, uses `/login?method=local`, and never prints a /login URL.

**Accounts** (usernames only):
- `admin@smartsched.local`: setup and API verification only.

- The gracious DB was restored by the orchestrator at about 14:30 UTC. That removed runs #9–#11, so later checks use run #7.

**By hand vs API:** every listed step was done in the browser, by clicking what a person would click. The API was used for:
- verification;
- the temporary forecast term (created, then deleted);
- the public-schedule switch, the IdP provider on/off switches and removal, `public_url`, and restoring the AI limits.

**Measurements:** the MOBILE.md snippets:
- M-13: ratio at rest and after a 300 px scroll.
- M-15: buffered `layout-shift` observer installed by `addInitScript`; session-window sum.
- M-16: Event Timing, longest entry of the tap.
- Root 200 % and 32 px root.
- 320×568 reflow.
- Grabber: CDP `Input.dispatchTouchEvent`, 20 steps of 25 px.
- Keyboard proxy: `visualViewport.height` shimmed to 508 + a `resize` event.
- Safe area: `Emulation.setSafeAreaInsetsOverride` (left/right 59, bottom 21).
- Contrast: computed text vs composited background.

**Mocks:** the repo's OIDC issuer `e2e/w3-idp-mock-issuer.py` on 19921, and my own SAML IdP mock (scratch `saml_idp.py`, modelled on `tests/test_rf12_saml_security.py`) on 19923. Its modes:

Both run with the backend venv's `python -I`; I killed only their PIDs afterwards.

**Specs:** `w3-idp.spec.ts` and `motion-audit.spec.ts -g helper`, run with `E2E_REAL=1 --trace=off --workers=1 --output=<scratch>`. Output was filtered for passwords; a `grep -F` of every output file for the admin password found 0 files. `AUDIT_TRACE=0` kept the motion audit from writing timeline traces into the repo; git status was unchanged.

**E2EB-F01 · major · /admin, /dashboard and /settings?tab=integrations jump on load at 390 and 768 (CLS 0.35–0.46)**

Repro:
1. Sign in as `e2eb.admin` (or the seeded admin) at 390×844 touch.
2. Open each route; install a buffered `layout-shift` observer before load.
3. Wait 2.5 s.

Observed:
- /admin: 0.423 (390) / 0.348 (768). One shift of a `DIV` at about 870 ms.
- /dashboard: 0.460 / 0.396. The big shift is `DIV[dashboard] + SECTION[dashboard-hero]` at about 840–1680 ms.
- /settings?tab=integrations: 0.441 / 0.427. `DIV[calendar-push-admin]` at about 820 ms, then `DIV[cal-admin-export]`.

Expected: ≤ 0.1 (MOBILE.md M-15; > 0.25 on a primary screen is major).

Where:
- `components/dashboard/dashboard-view.tsx` (hero);
- `components/settings/calendar-push-admin.tsx`;
- the /admin overview.

These are the numbers FIX-B (queued 13:55) lists as "was", so the fix is likely not in this build (70f237b).

Proposed fix (as FIX-B):
- reserve the hero's and the welcome "Başlarken" card's height with a skeleton of the same size;
- render `calendar-push-admin` with a fixed-height placeholder until its query settles, instead of mounting late;
- re-measure on the next build.
