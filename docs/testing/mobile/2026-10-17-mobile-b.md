## 2. Method

- **M-01…M-11, M-13** are the MOBILE.md snippets, verbatim (`ev/scripts/lib.mjs`). M-02 scrolls in steps of 0.8 × viewport height and merges the results. A battery runs on every route, step, tab, sheet, dialog and filter state the route has.
- **M-04 on tablet:** a bottom sheet, or a centred dialog / side sheet 360–640 px wide and no taller than the viewport (MOBILE.md §2).
- **M-05:** the primary from the route matrix, measured at scroll 0, 400 and the end. A primary reported as "covered" was probed again with `elementFromPoint`. `compare-apply`, `move-confirm`, `publish-confirm` and `reset-confirm` read "covered" only because they are **disabled** until a choice is made (`pointer-events: none`). That is not an overlay, so those rows count by position only.
- **M-08:** `calendar-mobile` / `day-timeline` / `agenda` at 390; at 768, a day / building view with chips ≥ 72 px, checked on the screenshot (the probe's ids do not cover "Pano").
- **M-12:** layout viewport shrunk by 336 / 400 px. Fields: the program wizard's first field, the learning reset reason and the solver number input.
- **M-14** (advisory): the motion-audit rAF and LoAF probe around each tap. The INP column is the worst interaction on that document so far.
- **CLS:** a buffered `layout-shift` observer injected before any script. The reported value is the **web-vitals session window** (max 5 s, gap 1 s); the document sum is shown next to it. Shifts within 500 ms of an input are excluded by the API. Steps of one SPA document (Studio steps, tabs) inherit the window of the earlier step on the same document, so the first state that shows a value is the one to fix.
- **Contrast:** text colour against the first opaque ancestor background, 4.5 : 1 (3 : 1 for large text). Disabled and `aria-hidden` text are skipped.
- **Safe area:** `Emulation.setSafeAreaInsetsOverride` (top 47, bottom 34), then the tab bar gap, `#main` padding, header padding and the floating capsules.
- **Text 200 %:** `Page.setFontSizes` standard 16 → 32 px, which is what Android "font size" and the rem-based CSS respond to. The 1×1 skip link "İçeriğe atla" is ignored (sr-only by design).
- **Dark:** `colorScheme: "dark"`; next-themes follows the system. On dark passes, only M-01, M-04, contrast, CLS, errors and screenshots were taken: M-02 / M-03 / M-05 / M-07 / M-09 / M-10 do not depend on the theme.

## 4. Per-route results

Each table gives phone 390 and tablet 768, light, then the dark contrast row. "Measurement" holds the numbers the snippets returned (phone / tablet). Screenshot paths are relative to the scratchpad. CLS is the session-window value; *doc sum* is the whole document. These tables are generated by `ev/scripts/analyse.mjs` from the JSON. The M-05 "covered" rows of disabled primaries and the "NOT RUN" rows are explained in §2 and §7.

Three more ways to read these tables:

- **NOT RUN in the tablet column** means the state does not exist at 768. Examples: the timetable has a sidebar instead of the filters sheet, `/admin/users` and `/admin/audit` keep their filters inline, Studio has no classes-filter trigger.
