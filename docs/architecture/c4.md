# C4 context and containers

Two levels of the [C4 model](https://c4model.com/): who and what SmartSched talks to (level 1), and the
containers of one deployment (level 2). Index: [README.md](README.md).

## Level 1: system context

```mermaid
flowchart LR
  subgraph people["People (roles from roles / permissions)"]
    admin(["Administrator<br/>setup, users, AI and KVKK switches"])
    planner(["Planner<br/>import, rules, solve, publish"])
    teacher(["Academician (TEACHER)<br/>my classes, requests, bookings"])
    staff(["Staff who book rooms<br/>booking grid, my bookings"])
    approver(["Approver<br/>approval scopes"])
    public(["Anyone with a link<br/>public schedule, .ics feed"])
  end

  smartsched["SmartSched<br/>timetable solver, room booking,<br/>AI helper (optional)"]

  subgraph ext["External systems (each off until an administrator configures it)"]
    idp["Identity providers<br/>Microsoft Entra ID, Google Workspace,<br/>any OIDC issuer, SAML, LDAP directory"]
    mail["Outgoing mail<br/>SMTP (password or OAuth)"]
    cal["Calendars<br/>Google Calendar and Microsoft 365 push,<br/>calendar apps subscribe to .ics feeds"]
    ai["AI providers<br/>Anthropic, OpenAI-compatible (incl. a local Ollama),<br/>Gemini, speech-to-text for voice input"]
    chan["Notification channels<br/>web push, Telegram, WhatsApp, SMS, Teams / Slack"]
    hooks["Outgoing webhooks<br/>HMAC-signed"]
    crbs["classroombookings (CRBS) legacy<br/>PHP + MySQL: dump or DSN import, upgrade"]
  end

  files[/"Office workbooks and files<br/>planning list, exam list, weekly grids,<br/>room master, any file for the council"/]

  admin & planner & teacher & staff & approver --> smartsched
  public -- "token or public link, read only" --> smartsched
  files --> smartsched
  smartsched -- "OIDC / SAML / LDAP bind" --> idp
  smartsched -.-> mail
  smartsched -.-> cal
  smartsched -. "only routed features, KVKK transfer basis" .-> ai
  smartsched -.-> chan
  smartsched -.-> hooks
  crbs -- "read once (import / upgrade)" --> smartsched
```

Everything to the right is optional: import, solving, the booking grid and manual edits work with no external system
at all. Dotted arrows leave the server only after an administrator has entered the institution's own sender, client
or key, and (for personal data) recorded a KVKK sign-off; outbound calls go through an outbox or the AI gateway,
never straight from a request handler. CRBS is a data source only; SmartSched never writes back to it.

## Level 2: containers (docker compose)

```mermaid
flowchart TB
  browser(["Browser<br/>desktop and phone"])
  calapp(["Calendar app"])

  subgraph host["One Docker host: smartsched/deploy/docker-compose.yml"]
    caddy["caddy<br/>HTTPS edge, ACME<br/>(docker-compose.caddy.yml, --tls)"]
    proxy["proxy: nginx (unprivileged, :8080)<br/>security headers, CSRF origin fence,<br/>no API docs, no /metrics"]
    frontend["frontend: Next.js 16 + React 19<br/>pages in src/app, BFF route handler<br/>src/app/api/v1/[...path] (cookie → bearer)"]
    subgraph be["backend: FastAPI + uvicorn (2 workers)"]
      api["API routers /api/v1"]
      jobs["in-process jobs: run / import / council queue,<br/>integrations outbox, approvals sweeper,<br/>reminders, nightly jobs"]
      cpsat["OR-Tools CP-SAT<br/>in a worker thread"]
    end
    db[("db: PostgreSQL 16<br/>row-level security")]
    uploads[("uploads volume<br/>room photos, staged workbooks")]
    subgraph obs["profile observability (optional)"]
      prom["prometheus"]
      loki["loki"]
      alloy["alloy"]
      grafana["grafana (/grafana/, admins)"]
    end
    ollama["ollama (profile ollama, optional)<br/>OpenAI-compatible, internal only"]
    subgraph legacy["profile legacy (optional)"]
      crbs["crbs (php-apache)"]
      crbsdb[("crbs-db: MySQL 8.4")]
    end
  end

  browser --> caddy --> proxy
  browser -. "without --tls" .-> proxy
  calapp -- ".ics token feeds" --> caddy
  proxy -- "pages, /_next, /api/*" --> frontend
  proxy -- "token .ics feeds, security.txt, room photos" --> api
  frontend -- "HTTP, bearer JWT" --> api
  api --- jobs
  jobs --> cpsat
  api & jobs --> db
  api --> uploads
  api -. "internal URL" .-> ollama
  prom -- "scrape /metrics (internal network)" --> api
  alloy -- "container logs" --> loki
  alloy -- "host and Postgres metrics" --> prom
  grafana --> prom & loki
  proxy -- "/grafana/ after admin check" --> grafana
  crbs --> crbsdb
  api -. "CRBS import by DSN" .-> crbsdb
```

The browser never talks to FastAPI directly: nginx sends every `/api/*` request through the Next.js route handler,
which keeps the JWT in an httpOnly cookie and adds the bearer header; only the token feed URLs, `security.txt` and
room photos go straight to the backend. There is **no separate worker container**: solver runs, imports, council
jobs, outboxes and sweeps run as asyncio jobs inside the backend process, and CP-SAT runs in a thread off the event
loop (a dedicated worker service is listed as planned under "Scaling" in the deploy README). Profiles stay off
unless `deploy.sh` is asked for them.
