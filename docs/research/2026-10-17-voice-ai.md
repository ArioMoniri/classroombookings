## 0. BLUF

1. **Claude has no audio input and no speech-to-text or text-to-speech in its API (checked 2026-10-17).** The
   Messages API accepts these content blocks: `text`, `image`, `document`, `search_result`, tool blocks and
   thinking blocks. It has no `audio` or `input_audio` block ([Messages API reference][anth-msg]). The features
   overview lists text, images, PDFs and files, and nothing for audio ([Features overview][anth-features]).
   Voice in Claude Code (`/voice`, March 2026) and in the claude.ai apps turns speech into text before the model
   sees it. That transcription endpoint is not part of the public API ([third-party PR][cc-voice-pr], unofficial).
   **"Native Claude voice" is therefore not possible today.** Claude stays the text model. A separate
   speech-to-text (STT) step feeds it text.
2. **Recommended design: STT, then the existing text pipeline.** The transcript goes into the same box the user
   would type in. The user sees it and can edit it before sending. On send, the same guardrails, injection check,
   personal-name redaction (`app/ai/personal.py`), limits and metering run as for typed text, because nothing
   downstream changes. Voice becomes one new gateway feature, `voice_stt` (optional `voice_tts` later). Admins
   route it per feature in /admin/ai, with the same encrypted keys, model sync, test call, fallback and KVKK
   transfer record as every other feature. All of it lives in the shared `settings` table, so every admin sees the
   same configuration.
3. **"Whole process" (audio in, answer out from one model)** exists on Gemini (audio in `generateContent`, Live
   API) and OpenAI (Realtime, `gpt-realtime`). It is **not recommended as the default**. It bypasses the text input
   guard: the model has heard the audio before any check could run. It cannot apply the per-person name redaction,
   which also cannot redact images (personal.py says so for images). It replaces Claude for that turn, loses the
   chat tools' grounding, and costs 5–20× more per minute. Keep it as a later, flag-gated option (VO-12).
4. **Recommended default STT for Turkish under KVKK: local Whisper large-v3-turbo.** It runs on faster-whisper in
   the `speaches` container (MIT, OpenAI-compatible `/v1/audio/transcriptions`). The gateway registers it as the
   existing `openai_compatible` provider with the local-server opt-in, so no audio leaves the institution and no
   transfer record is needed (`gateway.transfer_ok`, gateway.py:252). Per-minute cost is zero.
   - **Cost:** about 2–2.5 GB RAM and 2 CPU threads, on a pod that is already over-committed. Section 6 covers the
     sizing.
   - **Quality fallback:** an EU-region cloud route with a notified KVKK standard contract. The candidates are
     Azure (AI Speech fast transcription `tr-TR`, or Azure OpenAI `gpt-4o-transcribe` in an EU data zone) and
     Google (Vertex AI EU, Chirp 3 or Gemini transcribe). The admin chooses.
   - **Never in production:** the browser's cloud Web Speech recognition, because Chrome sends the audio to
     Google.
5. **Blocker found in the deployment.** `Permissions-Policy: … microphone=()` is set in
   `deploy/nginx/default.conf:108` and `deploy/caddy/Caddyfile:24`. It disables `getUserMedia` on every page, so
   no microphone works until it becomes `microphone=(self)` (ticket VO-05).

### 2.4 In the browser

- **Web Speech API (`SpeechRecognition`).** By default recognition runs on a server: "Your audio is sent to a web
  service for recognition processing". In Chrome that service is Google's. Under KVKK this is an uncontrolled
  transfer abroad with no contract, so it is **forbidden for production**. There is a newer **on-device** mode:
  `processLocally = true`, with `SpeechRecognition.available({langs:['tr-TR'], processLocally:true})` and
  `install()`. In that mode "neither the audio nor the transcribed speech are sent to a third-party service"
  ([MDN][mdn-ws]). The design uses it **only** for optional live *interim* captions, only when on-device tr-TR
  reports `available`, and never as a source of the final text.
- **MediaRecorder:** pick the format with `MediaRecorder.isTypeSupported`. Use `audio/webm;codecs=opus` on
  Chromium and Firefox, and fall back to `audio/mp4` (AAC) on Safari/iOS. OpenAI, Gemini and Whisper (ffmpeg)
  accept both. At 24–32 kbps, Opus makes 120 s ≈ 0.4–0.5 MB.
- **Chunked upload vs. streaming.** v1 records a clip, uploads it once (≤ 120 s) and transcribes it: one request,
  simple metering, works with every provider and with local Whisper. Streaming (WebSocket from the browser to our
  backend, relayed to a provider's streaming API, or WebRTC to OpenAI Realtime) gives live captions, but it needs a
  relay or browser-side provider tokens. Browser tokens would also need CSP `connect-src` exceptions (today
  `connect-src 'self'`, `frontend/src/proxy.ts:42`). Streaming is v2 (VO-11), relayed through our server so keys
  and the CSP stay as they are.
- **VAD:** server-side Silero VAD in faster-whisper trims silence. In the browser, an `AnalyserNode` RMS level
  meter can auto-stop after about 2 s of silence (no worklet or wasm needed, so CSP `script-src` with
  `strict-dynamic` is not touched). `@ricky0123/vad-web` (ONNX in wasm) would need `'wasm-unsafe-eval'`, so it is
  not used.
- **Permissions:** `getUserMedia` needs a secure context (HTTPS) and **`Permissions-Policy: microphone=(self)`**.
  The current headers say `microphone=()` (`deploy/nginx/default.conf:108`, `deploy/caddy/Caddyfile:24`), which
  blocks the microphone. CSP `media-src 'self' blob:` already allows playback of recorded and TTS blobs
  (`proxy.ts:43`).

### 2.5 KVKK points

- A voice recording is personal data. It becomes **special-category biometric data** only when it is processed to
  identify the speaker. Transcription does not identify anyone, so it stays ordinary personal data. Voice-print
  features (speaker ID, diarization tied to accounts) are therefore excluded.
- Transfers abroad (amended KVKK Art. 9, Law 7499, 2024). The basis is adequacy (none granted yet), appropriate
  safeguards (a **standard contract, notified to the Authority within 5 business days**, or binding corporate
  rules), or narrow derogations. Explicit consent is now only an occasional-transfer derogation, so it **cannot
  be the basis for routine cloud STT** ([Erdem & Erdem][kvkk-sc], [Cottgroup][kvkk-cott]). The existing per-provider
  transfer record (`kvkk_mechanism`, `gateway.py:252`) already models this.
- Per-user **explicit consent is still required for the processing choice.** Voice is optional, typing is always
  available, and the user is told where their voice goes. This works like `ai_personal` (`services/kvkk.py:90`).

## 3. Design

### 3.1 Gateway shape (provider-agnostic)

```
browser ──(clip ≤120 s, webm/opus|mp4)──► POST /api/v1/ai/voice/transcribe (feature=<target>, lang=tr)
   │                                          │ consent `voice` active? voice enabled? clip caps (bytes, seconds, mime)
   │                                          │ route = resolve_route("voice_stt"); transfer basis (PERSONAL_FEATURES)
   │                                          │ rate + concurrency + reserve audio seconds (ai_usage limits)
   │                                          │ SpeechAdapter.transcribe(...)  ── one retry on the route's fallback
   │                                          │ meter one ai_usage row (feature=voice_stt, audio_ms, cost, target)
   │◄──── {text, duration_s, language, provider_local, warnings} ─┘  (audio bytes dropped, never written)
   ▼
same text box (editable) ──► existing endpoint (/chat/stream, /elicit, …) ──► existing pipeline:
                              input guard, injection check, redaction, limits, metering (feature=chat/rules/…)
```

- **New package `app/ai/voice/`:**
  - `speech.py`: the `SpeechAdapter` ABC (`transcribe(audio: bytes, mime, *, language, prompt) -> Transcript`,
    `list_models()`, `translate_error()`) and `Transcript{text, duration_s, language, confidence|None,
    provider_usage}`.
  - `openai_audio.py`: one adapter for `openai`, `azure_openai`, `openrouter` (if it serves audio) and
    `openai_compatible` (local speaches). It calls `POST {base}/audio/transcriptions`, multipart, with `model`,
    `language=tr` (`languages` for `gpt-transcribe`), `prompt` = vocabulary and `response_format=json`.
  - `gemini_audio.py`: inline audio part plus the instruction "transcribe verbatim in Turkish; output only the
    transcript" with a JSON schema `{text}`. The instruction is fixed and the audio is untrusted data. The output
    guard still applies.
  - `fake.py`: test only. It is selected by `pipeline.TEST_TRANSPORT`-style injection, never through the registry
    (keeps the no-mock audit clean).
  - `run.py`: `run_transcription()`, which reuses `pipeline` pieces (`_RATE`, `_CONCURRENCY`,
    `meter.reserve/record/settle`, the fallback loop).
- **Registry:**
  - `ProviderSpec.capabilities: frozenset[str]` ∈ {`text`, `stt`, `tts`, `audio_native`}. Anthropic, Bedrock
    and Vertex (Claude) get `{text}`; OpenAI and Azure OpenAI get `{text, stt, tts, audio_native}`; Gemini gets
    `{text, stt, audio_native}`; openai_compatible gets `{text, stt, tts}` (whatever the server lists).
  - **Later:** speech-only providers `azure_speech`, `deepgram`, `google_stt` (Chirp, Vertex EU) with
    `capabilities={stt}` (VO-10).
  - `ModelInfo.modalities` is filled at sync. For OpenAI-style lists, ids containing
    `transcribe|whisper|live-transcribe` give `stt`, and `tts` ids give `tts`. Gemini models with audio input give
    `stt`. speaches `/v1/models` lists the faster-whisper models. `validate_route` refuses a `voice_stt` route to a
    model without `stt` (new code `model_not_speech`, TR/EN).
- **Features:** `voice_stt` and `voice_tts` go into `FEATURES`, `FEATURE_LABELS` ("Sesle yazma" / "Voice input",
  "Sesli okuma" / "Read aloud") and `PERSONAL_FEATURES`. `DEFAULT_CAPS["voice_stt"] = {timeout_s: 60,
  max_audio_s: 120, max_bytes: 5_000_000}`. `ai_usage.feature` is `String(16)`, and `voice_stt` fits.
- **Route:** `voice_stt` has its own route (provider, model, fallback). It never falls back to the global *text*
  default, because a Claude default cannot transcribe: `resolve_route` returns source `"none"`, and the UI hides
  the mic with "Ses için bir model seçilmedi". There is one STT route for all surfaces. Per-surface STT routes are
  not needed: `feature=<target>` is a meter tag, not a route.
- **Settings `ai.voice` (JSON, no migration):**

  ```
  enabled: false
  consent_required: true
  max_seconds: 120
  max_seconds_by_target: {booking_nl: 45}
  retention_days: 0
  local_only: false
  vocabulary: "catalog"   # catalog | off
  live_captions: "on_device"   # on_device | off
  tts_enabled: false
  ```

  - `local_only` refuses any route whose provider is not local.
  - `max_seconds_by_target` keeps the transcript within the target's `MAX_INPUT_CHARS`: 45 s of speech is about
    700–900 characters, under booking_nl's 1000.
  - `vocabulary: catalog` sends room codes, building names and course codes from the catalog as the STT prompt,
    which biases the model toward "B-204" and "MAT 101". It **never sends people's names** unless the person has
    the `ai_personal` grant (personal.py rules).

### 3.2 Flow and guardrails

1. The mic button is pressed (or held, on phones). On first use the consent sheet appears. Then the browser asks
   for the microphone.
2. The clip is recorded (level meter, timer, auto-stop at `max_seconds` or after 2 s of silence). Optional
   on-device interim captions are shown.
3. Upload goes to `POST /ai/voice/transcribe` (multipart, `feature`, `lang`). The server checks consent, enabled,
   mime allowlist (`audio/webm`, `audio/ogg`, `audio/mp4`, `audio/mpeg`, `audio/wav`), magic bytes, size and
   duration. Duration comes from the container header, falling back to bytes ÷ bitrate, and must be ≤ the cap. The
   body is read into memory with a hard byte cap, using `UploadFile.read(max+1)`, and never touches disk
   (`SpooledTemporaryFile` threshold above the cap).
4. The provider is called, and the transcript is cleaned: control characters stripped
   (`sanitize.strip_controls`), Unicode NFC applied, length capped.
5. **The transcript is not guarded or sent anywhere else at this point.** It goes back only to the same user and
   lands in the text box, flagged `source=voice` in the UI. The user can edit it before sending.
6. On send, the existing endpoint runs the full pipeline with `user_text` = the edited text: scope check,
   injection check (TR/EN folding), redaction, limits and output guard. A spoken injection is caught exactly like a
   typed one, and the VO-09 fixture proves it.
7. Optional "send directly" (no review step, an admin switch, default off) takes the same path. Only the review
   step is skipped.

### 3.3 Metering and limits

- `ai_usage` gets **`audio_ms` (Integer, default 0)** and **`modality` (String(12): `text` | `audio_in` |
  `audio_out`, default `text`)**. Migration at the **next head** (see collisions). `detail` holds the target
  surface (`target=chat`), never content. `prompt_sha256` becomes the SHA-256 of the audio bytes (useful for
  duplicate detection, never reversible).
- Cost: per-minute prices are taken from the synced price when the provider publishes one, else from a new
  `STT_PRICE_TABLE` beside `PRICE_TABLE_VERSION` in `client.py`. Examples: gpt-transcribe 0.0045, gpt-4o-transcribe
  0.006, gpt-4o-mini-transcribe 0.003, whisper 0.006, local 0. Gemini audio tokens are priced at the model's
  audio-in rate × 32 tok/s. The cost counts toward the existing org USD budget.
- New limits in `ai.limits` (no migration): `user_daily_audio_s` (default 600 = 10 min), `user_monthly_audio_s`
  (default 6 000), `org_monthly_audio_s` (0 = none), plus the same `roles{}` / `users{}` overrides with
  `audio_daily` / `audio_monthly`. A reservation of `max_seconds` happens before the call and is settled with the
  real duration. Refusals are 429 `ai_voice_limit_reached` (TR/EN).
- The existing rate limits (30/min, 2 concurrent per user) apply to voice calls too. Local Whisper also has a
  global queue of 1–2 concurrent jobs, so the solver keeps its CPUs.
- Reports: `/ai/admin/usage` gains `audio_minutes` per user, feature and day. Profil › Yapay zekâ kullanımım shows
  "Ses: 3 dk / 10 dk bugün".

### 3.4 KVKK

- **Consent purpose `voice`:** "Sesimin yazıya dökülmesi (sesli giriş)" / "Transcribing my voice (voice input)".
  The consent sheet names the configured provider and where it runs. Local: "Sesiniz kurum sunucusunda yazıya
  dökülür; dışarı gönderilmez." Cloud: "Sesiniz {sağlayıcı} hizmetine ({bölge}) gönderilir, yazıya döküldükten
  sonra silinir; ses kaydı saklanmaz." It has Allow and Not now buttons, and withdrawing is possible from Profil ›
  Gizlilik. Without an active grant, the endpoint returns 403 `voice_consent_required` and the UI opens the sheet.
- **No audio stored by default** (`retention_days: 0`). The bytes live only in the request's memory. Logs never
  contain audio or transcript (the existing AI log rules). If admins set 1–7 days for troubleshooting (VO-12
  later, not v1), clips are encrypted in uploads, listed in the DSR export and purged by `deploy/purge-uploads.sh`.
- **Transfer record per provider:** `voice_stt` is in `PERSONAL_FEATURES`, so a cloud provider without
  `kvkk_mechanism` gets 409 `ai_transfer_basis_missing` (existing behaviour). Local (`openai_compatible` with a
  private URL) needs none. The record form gains a "processes voice" checkbox and the provider's audio retention
  (e.g. OpenAI EU project: zero retention; Gemini paid: abuse-logging period; Deepgram EU: per contract).
- **DSR:** there is nothing to export beyond the `ai_usage` rows (already per user) and the consent rows.
- `ai_personal` withdrawal: the vocabulary prompt drops people's names. A transcript that contains a name is
  redacted on send like typed text.

### 3.5 "Whole process" mode

| | STT then text (default) | Native audio (Gemini, OpenAI Realtime) |
|---|---|---|
| Model answering | the routed text model (Claude by default) | the audio model |
| Input guard / injection check | on the edited transcript, before the model | only after the fact (on the model's own transcript); the model already heard the audio |
| Personal-name redaction | yes | **no** (binary audio, like images) |
| User can correct mis-heard words | yes | no |
| Tools (chat proposals, apply) | unchanged | must be re-implemented per provider |
| Cost / min | $0–0.006 | ≈ $0.005–0.03 in + output |
| Latency | clip length + 1–3 s | sub-second turn-taking |

The recommendation is STT then text everywhere in v1. Native mode is VO-12 (later, behind
`ai.voice.native_mode=false`). It is only for an optional hands-free "sesli asistan" in chat and must satisfy all
of these:

- it asks the model for the transcript first and runs `check_user_input` on it before any tool call is allowed;
- tools stay limited to read-only ones;
- it applies only when the person has the `ai_personal` grant;
- the provider has a transfer record.

### 3.6 Local Whisper container (memory on the 8 GB pod)

- **Image:** `speaches`, CPU compose variant, pinned by digest (`deploy/pin-digests.sh`, `deploy/pins.py`).
  - Model: `deepdml/faster-whisper-large-v3-turbo-ct2`, int8, pre-fetched into a volume at build or first start,
    with no egress afterwards.
  - Settings: `WHISPER__COMPUTE_TYPE=int8`, `cpu_threads=2`, VAD on, `language=tr` default.
- **Compose profile `voice-local`** (off by default). It joins the internal network only, with no published port.
  The backend reaches it at `http://whisper:8000/v1`; the admin enables `openai_compatible` with `allow_local`.
- **Memory today:** the compose limits add up to ≈ 9.5 GB on an 8 GB host:

  | Service | Limit |
  |---|---|
  | db | 2 g |
  | backend | 4 g |
  | frontend | 1 g |
  | proxy | 0.25 g |
  | crbs-db | 1 g |
  | crbs | 0.5 g |
  | prometheus, loki, alloy, grafana | ≈ 0.77 g |

  Limits are caps, not reservations, but the pod has no headroom.
- **Proposal:** a whisper limit of **2.5 g** with reservation 1.8 g, `cpus: 2`. The turbo int8 RSS is estimated
  at 1.5–2.5 GB, and VO-05 must measure it. With the profile on, the README recommends:
  - turning off the legacy CRBS pair (−1.5 g) once migration is done, or
  - `BACKEND_MEMORY=3g`;
  - otherwise using `small` (≈ 0.9–1.5 GB, faster, noticeably worse Turkish).

  CPU contention with CP-SAT solves (4 cores): the whisper queue holds 1 job, and the README says a solve plus
  dictation can slow both. A GPU or a separate small VM, at the same `base_url`, is the clean scale-out path.
- **Latency target (to measure):** a 10 s clip transcribed in ≤ 6 s on 2 threads with turbo int8. If that is
  missed, the default model is `small` or a cloud route.

## 5. Owner questions (each with a recommended default)

1. **Default STT provider?** Recommended: local Whisper large-v3-turbo (container) where the pod can host it.
   Otherwise an EU cloud route with a notified standard contract.
2. **Which cloud fallback?** Recommended: Azure (AI Speech fast transcription `tr-TR` or Azure OpenAI
   `gpt-4o-transcribe`, EU region), because the gateway already has `azure_openai`. Second choice: Google Vertex
   EU (Chirp 3 / Gemini transcribe), which has the best published Turkish numbers but needs a new speech provider.
   Decide after the VO-09 Turkish bench.
3. **Review before send, or send directly?** Recommended: always review (the transcript is editable). The admin
   switch "send directly" stays off.
4. **Store audio?** Recommended: never (`retention_days: 0`). There is no troubleshooting retention in v1.
5. **Per-user limits?** Recommended: 10 min/day, 100 min/month. Admin/planner roles can be raised in Limitler.
6. **Quick reserve before booking_nl exists:** plain dictation into the note field, or wait? Recommended: wait.
   Voice should arrive there with booking_nl so a spoken request fills the form.
7. **Whole-process / native audio (Gemini Live, OpenAI Realtime)?** Recommended: not now (VO-12 later, flag off,
   chat only, read-only tools).
8. **Read-aloud (TTS)?** Recommended: later (VO-13). Use the browser's `speechSynthesis` first, which costs
   nothing and has no upload; note that some Chrome voices are network voices. Provider TTS only on request.
9. **Live captions?** Recommended: on-device only (Chrome on-device `tr-TR` when available), otherwise "after
   stop". Server-relayed streaming captions (VO-11) only if users ask.
10. **Turn off the legacy CRBS containers or lower BACKEND_MEMORY to fit whisper?** Recommended: enable whisper
    only after the CRBS migration is done and the CRBS pair is off.
