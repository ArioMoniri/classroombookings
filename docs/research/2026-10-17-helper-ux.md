# AI helper ("Yardımcı"): search, "where is it" and generative action cards — UX research (2026-10-17)

Ledger `helper-ux-2026-10-17`. Research for [`docs/design/v3/helper.md`](../design/v3/helper.md). Tickets: ROADMAP §
"AI helper: search, \"where is it\", generative actions (owner request 2026-10-17) — UX", HX-01…HX-12. The backend
(HB-xx) is designed by a parallel architect agent in `docs/research/2026-10-17-ai-helper-architecture.md`; that file
did not exist yet when this one was written (2026-10-17 ~23:50 UTC). §7 lists what the UX needs from it.

Owner request (2026-10-17): keep every feature, but make SmartSched easy and never overwhelming for admins and
academicians who are used to classroombookings (CRBS). Add a search tool or AI guide that says where each feature is
and where to click. In chat, generate buttons and small forms for admin and academician tasks and call the site's own
features, "similar to OpenAI's new intelligent UI". Decide where it sits: a bot, a search bar, or both.

## 0. BLUF

1. **"OpenAI's new intelligent UI" is ChatGPT's *Intelligent UI*, announced on 2026-10-07 with GPT-6.** Answers mix
   text with native, streamable components: buttons, forms, checklists, charts, maps and small task tools. A compiler
   renders the interface while the model generates it. It is a ChatGPT end-user feature with no developer API (§1.1).
   The developer equivalents are **ChatKit widgets** (a typed JSON widget tree with actions) and the **Apps SDK on
   MCP Apps**.
2. **The whole field agrees on one safety rule: the model picks from a catalogue of trusted components and sends data,
   never code.** This is how A2UI, ChatKit widgets, AI SDK tool parts, CopilotKit and assistant-ui work. MCP Apps is the
   exception: it sandboxes server-written HTML in an iframe. We adopt the catalogue rule. The model never writes HTML or
   JavaScript.
3. **No new runtime library is needed.** We already have the SSE client (`components/chat/chat-stream.ts`), the
   composer (`PromptComposer`), zod 4, cmdk 1.1, react-joyride 3.2, motion 14 and the AI usage banner. A card registry
   of about 300 lines is smaller and easier to audit than assistant-ui (MIT) or CopilotKit (MIT). ChatKit (OpenAI-hosted;
   Agent Builder shuts down on 2026-11-30) and Thesys C1 (a proprietary hosted API) are ruled out by KVKK and by the
   rule that we never depend on a vendor. A2UI (Apache-2.0) is the schema we copy ideas from, and HX-12 maps to it later.
4. **The product references converge on the same placement:**
   - one search field that also asks the assistant (Notion "Search all sources with AI", ClickUp "Search, run a
     command, or ask a question… Ask AI", Evernote "Standard | AI-Powered", Raycast Quick AI from root search);
   - a side panel for the conversation (Linear, Asana, HoneyBook, Stripe's drawer from the help icon);
   - writes that need a human click (Stripe "asks the user to confirm", the M365 Admin agent "the administrator
     remains in control of all actions", ChatGPT's "before making changes").
5. **Search and "where is it" must work without AI.** Notion and Raycast route to AI only after search fails. Our
   institutions may switch AI off or hit the limit. The feature index and the deterministic "Nerede?" answers are
   therefore plain client code, and AI is an add-on on top.

## 1. Generative-UI patterns (checked 2026-10-17)

### 1.1 OpenAI

| Item | What it is (sources) | What we take |
|---|---|---|
| **Intelligent UI** (ChatGPT, 2026-10-07) | It rolled out with GPT-6 ("Sol" on paid plans, "Luna" on Free/Go from 2026-10-08). Answers can include "graphics, tappable buttons, forms, charts, diagrams, and other interactive experiences", e.g. a recipe widget that scales to the guest count, checklists, maps, and multiple-choice follow-ups that narrow the answer. ChatGPT can also build small tools on demand (bill splitter, calculator). OpenAI built "a library of native, streamable components" and "a compiler" that renders the interface while the model generates it. Users can reduce how many visuals they get. It applies to the Chat tab only. No developer API was announced. ([MacRumors][mr], [TechCrunch][tc], [9to5Mac][9to5], [Unite.AI][unite]; OpenAI's own page "GPT-6 and Intelligent UI for everyone" ([openai.com][oai-gpt6]) answered 403 to our fetcher, so its wording here comes from the search index summary) | **Native, streamable components from a fixed library**, never model-written markup. **Multiple-choice follow-ups** that narrow a task (our "Hangi salon?" chips). A **user switch** for fewer visuals (our "Yalnızca metin" preference, §4 of the design) |
| **ChatKit widgets** | `WidgetRoot` → `Card` (with `confirm` / `cancel` actions, `status`, `asForm`) and `ListView`. Layout: `Box`, `Row`, `Col`, `Form`, `Transition`. Text: `Text` / `Markdown` (with `streaming`), `Title`, `Caption`, `Badge`. Controls: `Button`, `Select`, `DatePicker`. Actions are typed objects that the integration handles on the server. Agent Builder retires on **2026-11-30**; OpenAI now recommends a custom server-side agent ([ChatKit widgets][ck-w], [ChatKit guide][ck], [Advanced integrations][ck-adv]) | The **card with confirm / cancel** shape and **actions as typed payloads that the server handles**. Our card props stay a subset of this vocabulary (title, rows, fields, primary / secondary action, status) |
| **Apps SDK** (on MCP Apps) | ChatGPT has been "fully compatible with the MCP Apps spec" since 2026-02-22. Since 2026-05-27, the input of approval-required tools is delivered only after approval. Since 2026-06-12, users choose when connected apps ask for permission ("before making changes"). Host CSS variables are passed to widgets (2026-05-28) ([Apps SDK changelog][apps-cl]) | **Approve, then execute**: no write tool runs before the user's click. Card styling comes from our tokens, not from the model |

### 1.2 Libraries and protocols

| Name | Model | Version / licence (npm registry, 2026-10-17) | Fit for SmartSched |
|---|---|---|---|

CopilotKit and AG-UI support it ([a2ui.org][a2ui], [The Decoder][decoder]) | `@a2ui/react` 0.14.0, Apache-2.0 | **Closest to our design.** Our `HelperCard` keeps an A2UI-like shape (catalogue id + typed props + action ids), so a later adapter is cheap |
| **Thesys C1** | An OpenAI-compatible hosted endpoint that returns UI specs, rendered by its React SDK (Crayon) ([toolradar][thesys]) | Proprietary hosted API (freemium); `@crayonai/react-ui` 0.9.16 MIT; `@thesysai/genui-sdk` "see LICENSE.md" | **Ruled out**: a third-party processor in the loop (KVKK cross-border transfer) and vendor lock-in |

## 5. KVKK notes for the helper

- The helper must not create a new transfer: it uses the gateway (`app/ai/pipeline.py`) and its per-provider transfer
  record, redaction (`personal.py`) and metering (hash only, never prompt text).
- **Memory** holds structured items only (task kind, target label, time; preferences as key / value). It does not hold
  the conversation. Each item is visible and deletable, export and erasure are covered (DSR) and the retention limit is
  90 days. This matches the data-minimisation reading of KVKK Art. 4(2)(ç) and the welcome guide's approach
  (`welcome-guide.md` §6.5).
- The conversation itself lives in the browser session (`sessionStorage`) and is cleared on sign-out. The server keeps
  only `ai_usage` metadata.

## 7. What the UX needs from the architecture doc (HB-xx; for the architect agent)

1. `POST /helper/stream` (SSE) with the events of `chat-stream.ts` plus **`card`** (`{id, kind, v, props, permission,
   risk, expires_at}`) and **`where`** (`{feature_id}`). It must not edit timetables; that stays in the run chat.
2. **Server-side permission filtering** of the tools and cards offered to the model (the M365 pattern). A card the user
   cannot run is never emitted.
3. **Entity resolution on the server** (room, person, course, run → ids), as `app/ai/resolve.py` does. The model never
   sends ids or URLs.
4. **Preview endpoints** for R3 cards (publish: `publish_blockers` + `changes-since-publish` + affected counts).
5. **Memory API:** `GET /helper/memory`, `DELETE /helper/memory/{id}`, `DELETE /helper/memory`,
   `PUT /helper/memory/settings`, plus DSR hooks.
6. A gateway feature key **`helper`** (routing, limits, local / cloud flag for the status chip:
   `GET /ai/me/usage` + `{helper: {provider_kind: "local" | "cloud" | "off", region}}`).
7. An admin switch per card kind (`helper.cards.<kind>.enabled`) and a global "Yardımcı" switch.
